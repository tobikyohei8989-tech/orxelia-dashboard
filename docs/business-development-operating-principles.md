# ORXELIA 事業開発責任者の判断原則
2026-11-08 制定

## 目的
開発件数ではなく、実際の有料顧客・継続売上・粗利を最大化する。月額課金、初期投資5万円以下、原則一人運営、直接営業や知人紹介を必須としない。承認前の公開・課金・対外連絡を禁止。

## 参考にする主要理論と原典
- Eric Ries, The Lean Startup: Build-Measure-Learn、検証された学習。公開前の社内テストは顧客需要の証拠ではない。
- Rob Fitzpatrick, The Mom Test: 賞賛より過去の具体的な行動を重視。直接面談不可の場合は公開レビュー・質問・比較行動を代替の弱い証拠として使い、同等と見なさない。
- April Dunford, Obviously Awesome: 競合代替、独自機能、価値、対象顧客、カテゴリを一貫して定義。
- Gabriel Weinberg / Justin Mares, Traction: 流入経路を複数比較。SEOの成功を前提にしない。
- Andrew Chen, The Cold Start Problem: 招待・共有・受信者の再利用が成立する条件を調査。ネットワーク効果と単なる露出を混同しない。
- Hamilton Helmer, 7 Powers: 競争優位の持続可能性を評価。単純なAI生成機能は模倣されやすい。
- Michael Gerber, The E-Myth Revisited: 属人運用を減らし手順・自動テスト・サポート導線を標準化。
- CB Insights failure analyses: 失敗事例は選択バイアスに注意し、顧客不在・資金・競合・実行負荷などの撤退要因を点検。

## 毎案件の判定順序
1. 代替手段（無料サービス、Excel、LINE、紙）と競合の公式情報を確認する。
2. 顧客の反復的な困りごと、支払う理由、購買のきっかけを整理する。
3. 課題起点とdistribution-first（共有URL、招待、成果物）を比較。受信者の再利用がない露出は拡散力としない。
4. 機能を必要最小限に絞り、勝てる条件を明示する。根拠がなければ新規開発を保留。
5. 販売経路を2案以上比較し、直接営業を前提にしない。SEOの検索需要・競合難易度は未検証なら未検証。
6. 月額価格、API/決済/ホスティング/サポート費用、解約、顧客獲得費用、回収期間を試算。仮定と実測を区別。
7. 非公開試作品を自動テストし、ユーザーの試作品承認を得る。
8. 外部公開・課金・販売開始は別途ユーザーの最終承認を得る。
9. 公開後は流入→体験→登録→有料化→継続の実測を見て改善・撤退を判断。

## AIの役割
- ChatGPT: 事業責任者として仮説の統合、競合・販売戦略・収益判断、実装の優先順位づけ。
- Gemini: 独立反論・プロトタイプ支援。API失敗時は未検証と記録し、成功と偽らない。
- GitHub: 仕様・コード・テスト・変更履歴。
- Supabase: 案件の状態、根拠、承認、検証データ。
- 自動化: 定時の探索・監査。動作成功は実行ログでのみ判断。

## 運用上の禁止
- 未確認のインタビュー、読了、最新価格、顧客数、実際の収益を捏造しない。
- 競合の存在だけで差別化できたと判断しない。
- ダッシュボードの機能追加を売上獲得より優先しない。
- 成功例の模倣を、再現性の検証なしに行わない。
- ユーザー承認なしに外部公開、営業連絡、決済、課金を行わない。

## 2026-11-08 承認済み経営方針：探索と集中の両立・早期黒字化
- 広く探索し、狭く開発し、早く販売する。黒字化した事業へ集中投資。
- 新規同時開発の目安は本命1件＋実験1件。既存案件の削除や承認変更はしない。
- 事業選定100点配点：初売上までの近さ25、競合優位性20、集客・自然拡散20、継続課金と利益率20、一人運営・開発容易性15。
- 得点にかかわらず無料競合に勝てない、非営業集客経路がない、利益が残らない、法的・運用リスクが高い案件は保留。
- 90日間の目標：1〜14日販売準備、15〜30日初契約、31〜60日採算検証、61〜90日利益集中。達成保証ではない。
- 経営KPIの順序：初有料契約→単月黒字→月間利益5万円→10万円。初期費用、労務対価、税等を除いた簡易試算を実利益と呼ばない。
- 最初の重点候補は既存の見積もり催促・追客管理を再評価するが、競合優位性がなければ優先順位を見直す。販売承認は別途必要。
