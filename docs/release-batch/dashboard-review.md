今回は点検と提案のみ。アプリ、DB、本番設定の変更やNetlify本番公開は実施していません。

## 点検の範囲と限界

- 公開ダッシュボードのホーム、事業一覧、承認・販売、収支、設定を閲覧。Partner Linkのログイン入口も確認しました。
- 点検用ブラウザーは未ログインです。表示された0件は、そのブラウザーの状態であり、利用者の事業が消えたことを示しません。既存のログイン状態や事業データは変更していません。
- 公開版v122に対応する画面コードと、GitHub上の自動開発処理を確認しました。
- 既存の事業フロー構造検査、Partner Linkの人工集計・締め日・CSV・ページ分割の検査、人数枠の検査は成功しました。実データの登録・削除・販売承認・招待送信は行っていません。
- iPhone実機、ログイン後の実データ、稼働中のDB権限、決済、他社アカウントとの分離は今回未検証です。

## Partner Linkの販売までに別途確認する事項

月次20日締め、年間集計、予定人工と実働人工、CSVは実装と計算検査があります。「まだ作っていない機能」と一括りにはしません。ただし今回、ログインして実業務データで確認したわけではありません。

販売前には、実際の招待・登録・打診・承諾・辞退・取消・人工登録を通して確認します。他社ごとのデータ分離と権限、退会・解約、バックアップ、通知条件、利用料金、問い合わせ対応、利用条件も確認が必要です。請求金額照合や決済は、人工集計があることだけでは実装済みと判断できません。

ダッシュボード改善と、Partner Linkへの決済・多社利用機能の新規実装は別の作業範囲です。後者の完成を今回の画面更新だけで保証しません。

## 1回の本番公開へまとめる進め方

1. この改善案から対象を確定する。
2. 開発ブランチで実装し、人工データで検査する。本番データを使った破壊的な試験はしない。
3. 台帳・AI案件・承認・集計・収支が同じ事業IDでつながることを確認する。試作も実際の表示条件で検査する。
4. PC・スマホのプレビュー、変更一覧、検査結果、DB変更があれば移行・復旧方法、公開先、想定クレジットをまとめて提示する。
5. 利用者の最終承認後、検証済みの変更をまとめて1回のNetlify本番公開で反映する。

コード修正や検証の回数と、本番公開の回数は分けます。DBの移行・設定変更が必要な場合は別作業ですが、Netlifyの本番公開を繰り返して試験する運用にはしません。本番公開分はクレジット制の通常料金で1回15クレジット、閲覧・通信等は別です。
